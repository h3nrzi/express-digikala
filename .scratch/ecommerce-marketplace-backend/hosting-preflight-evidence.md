# برگهٔ شواهد پیش‌پایلوت میزبانی

این برگه را برای هر نامزد جداگانه تکمیل کنید و پاسخ‌های کتبی، صورت‌حساب یا برآورد قیمت، و شواهد آزمون را به آن پیوند دهید. آزمون فقط در staging و با دادهٔ ساختگی انجام شود؛ هیچ داده یا اعتبارنامهٔ production وارد آن نشود.

## نقطهٔ شروع از بررسی اسناد عمومی

در [پژوهش گزینه‌های میزبانی](./research/hosting-provider-options.md) به تاریخ ۱۷ نوامبر ۲۰۲۶، راهنمای عمومی ArvanCloud از backup افزایشی پنج‌دقیقه‌ای نام می‌برد ولی restore از PITR را هنوز در آینده توصیف می‌کند؛ صفحهٔ محصول در مقابل PITR را قابلیت سرویس معرفی می‌کند. مستند عمومی Liara برای PostgreSQL backup روزانه را شرح می‌دهد و PITR/backup چهارساعته را در منابع بررسی‌شده نشان نمی‌دهد. مستندات عمومی بررسی‌شده برای هیچ‌یک تعهد قابل استناد RPO≤۴h و RTO≤۸h را اثبات نکردند. این‌ها فقط سرنخ استعلام‌اند؛ پاسخ کتبی و restore واقعی هنوز لازم است.

## استعلام کتبی از ارائه‌دهنده

برای هر پاسخ، متن دقیق یا خلاصهٔ قابل استناد، تاریخ، نام سرویس/پلن و لینک یا شمارهٔ پیوست را ثبت کنید. «در مستندات عمومی پیدا نشد» را پاسخ مثبت یا منفی تلقی نکنید.

|---|---|---|
| محل واقعی اجرای API، worker، PostgreSQL و object storage چیست؟ آیا همه در یک منطقه‌اند؟ | | |
| محل backup، log/monitoring، build و control plane کجاست؟ دسترسی پشتیبانی به داده از کجا انجام می‌شود؟ | | |
| پشتیبان PostgreSQL با چه تناوبی ساخته و تا چه مدت نگهداری می‌شود؟ رمزگذاری و جداسازی دسترسی چگونه است؟ | | |
| PITR اکنون واقعاً قابل restore است؟ آخرین نقطهٔ قابل‌بازیابی، تناوب WAL/backup، مراحل restore و محدودیت‌ها چیست؟ | | |
| زمان/مسئول restore و هزینهٔ DB یا فضای جایگزین چقدر است؟ آیا RPO≤۴ ساعت و RTO≤۸ ساعت تعهد قراردادی است؟ | | |

| آیا محدودیت حساب، پرداخت، استفادهٔ تجاری یا خاتمهٔ خدمت وجود دارد که بر تداوم MVP اثر بگذارد؟ | | |

پیکربندی قیمت را با هدف ظرفیت مصوب بسنجید: ۱۰۰ نشست فعال، ۲۵ درخواست/ثانیه پایدار و جهش ۵۰ درخواست/ثانیه برای ۵ دقیقه؛ P95 API کاتالوگ ≤۵۰۰ms، سبد خرید ≤۸۰۰ms و ایجاد سفارش ≤۲s (زمان ارائه‌دهندگان بیرونی جداست). قیمت نهایی باید ظرفیت و مصرف واقعاً آزموده‌شده را نشان دهد، نه فقط حداقل پلن.

### پرسش تکمیلی برای نامزدها

- **ArvanCloud:** مستند راهنمای backup و صفحهٔ محصول دربارهٔ restore از PITR هم‌خوان نیستند. کتبی روشن کنید آیا restore از backup افزایشی/PITR همین حالا برای پلن موردنظر قابل اجراست؛ اگر هست، راهنما و زمان آخرین restore موفق را بدهید. RTO بازیابی کامل کلاستر/منطقه را جدا از failover یک گره پاسخ دهید.
- **Liara:** مستند عمومی PostgreSQL از backup روزانه می‌گوید. کتبی روشن کنید آیا backup با فاصلهٔ حداکثر چهار ساعت، WAL/PITR یا سازوکار دیگری برای رسیدن به RPO هدف موجود است؛ روش و محدودیت restore را مشخص کنید.

## تمرین restore در staging

### پیش‌نیاز و روش

1. staging را تا حد ممکن همسان با نامزد production بسازید: API و worker جدا از یک image، PostgreSQL و object storage در ناحیهٔ مورد بررسی.
2. حجم و الگوی دادهٔ ساختگی را نمایندهٔ برآورد MVP انتخاب و ثبت کنید. هیچ دادهٔ مشتری واقعی، پرداخت واقعی یا راز production استفاده نشود.
3. پیش از نقطهٔ بازیابی، markerهای ساختگی زمان‌دار در PostgreSQL بنویسید و فایل‌های آزمایشی با شناسه/هش در object storage بگذارید. زمان آخرین marker موفق پیش از شروع تمرین را ثبت کنید.
4. از backup زمان‌بندی‌شدهٔ عادی بازیابی انجام دهید (و PITR را جداگانه فقط اگر ارائه‌دهنده آن را کتبی تأیید کرده است). DB، فایل‌ها، API، worker و یک گردش آزمایشی end-to-end را بررسی کنید.
5. برای گردش end-to-end از سفارش/پرداخت واقعی استفاده نکنید؛ یک عملیات ساختگی که از API آغاز شود، توسط worker پردازش شود و نتیجهٔ آن قابل مشاهده باشد کافی است.

## بررسی دسترس‌پذیری از شبکه‌های پایلوت

برای هر نامزد، حداقل یک اینترنت ثابت و یک اپراتور همراه را از محدودهٔ پایلوت تهران/حومه بررسی کنید. نام ISP/اپراتور، شهر/محدوده، تاریخ، ساعت، نوع اتصال و نتیجه را ثبت کنید. از یک روش و endpointهای یکسان برای هر دو نامزد استفاده کنید.

- [ ] DNS و TLS دامنهٔ staging برقرار است.
- [ ] API عمومی staging پاسخ سالم می‌دهد؛ کد HTTP، خطا و latency ثبت شده است.
- [ ] گردش ساختگی API → worker با موفقیت پایان می‌یابد.
- [ ] دسترسی برنامه به PostgreSQL با تراکنش ساختگی تأیید می‌شود؛ DB را عمومی نکنید.
- [ ] خواندن/نوشتن و بازیابی فایل آزمایشی object storage از مسیر مجاز برنامه تأیید می‌شود.
- [ ] نتیجه در چند نوبت ثبت شده است؛ خطاهای موقت، timeout، DNS و latency P50/P95 گزارش شده‌اند.
